# Module contract (all agents must follow exactly)

Browser 3D racing game. Plain ES modules, no build step. Served by `python -m http.server 8000` from this folder.
UI text is **Japanese**. Code comments sparse, English.

Libraries (only these):
- three@0.169.0 via importmap in index.html:
  `"three": "https://cdn.jsdelivr.net/npm/three@0.169.0/build/three.module.js"`,
  `"three/addons/": "https://cdn.jsdelivr.net/npm/three@0.169.0/examples/jsm/"`
- mqtt.js 5.10.1 via `<script src="https://cdn.jsdelivr.net/npm/mqtt@5.10.1/dist/mqtt.min.js"></script>` → global `mqtt`. (PeerJS/WebRTC as the transport was dropped: no working free TURN relay, joins timed out across phone/strict NATs. MQTT stays the always-available transport and control plane. Native WebRTC is used only as a best-effort shortcut for `state` messages — `p2p.js`, STUN only, no TURN, no library; see net.js (v3).)

Existing, DO NOT rewrite (read them first): `data.js` (cars, abilities, passives, skill tree, gacha, economy, track, `computeStats`, `nodeCost`, `nodeBlockReason`), `save.js` (`getSave`, `persist`, `newCarRec`, `resetSave`, `loadGhost`, `saveGhost`; v6: `setPersistHook`, `replaceSave`, `backupSave`, `backups`).

## Coordinate conventions
- Y up. Meters. Car local forward = +Z. `heading` (radians, yaw): forward vector = `(sin h, 0, cos h)`; `mesh.rotation.y = heading`.
- Car length ≈ 4.2 m, wheels touch y=0 of the car group.

## game.js
```js
// Mounts into document.getElementById('game') (UI makes it visible before calling, hides after).
// Creates its own WebGLRenderer + HUD DOM inside #game; removes everything on stopRace().
export async function startRace(opts) -> void
opts = {
  mode: 'solo' | 'ghost' | 'split' | 'online',
  players: [ { name, carId, look, stats /* computeStats() result */, control: 'p1' | 'p2' | 'net', pid? } ],
    // solo/ghost: 1 player control 'p1'. split: 2 players 'p1','p2'. online: all roster players;
    // the local one has control 'p1', remote ones 'net'; each has pid (string) from the net roster.
    // Grid order = array order.
  cpuCount?: number,            // solo only (default 3). Game picks random CARS + random unlocked nodes for CPUs.
  ghost?: ghostData | null,     // ghost mode: data to replay (see ghost.js). null → no ghost car.
  net?: NetSession, localPid?: string,   // online only
  onFinish(result),             // called once when the local player(s) finished and results are known
  onQuit(),                     // player pressed Esc → confirm → quit. Game calls stopRace() itself before onQuit.
}
result = {
  mode,
  placements: [ { name, carId, time /* seconds or null=DNF */, isLocal:bool, control } ],  // sorted 1st→last
  locals: [ { control:'p1'|'p2', carId, place /*1-based*/, time, bestLap } ],
  ghostRecording: ghostData | null,   // solo & ghost modes: recording of the p1 run (only if finished)
  beatGhost: bool | null,             // ghost mode: finished faster than the ghost; else null
}
export function stopRace() -> void    // idempotent
```
Controls (KeyboardEvent.code): solo/ghost/online: WASD **or** arrows drive, `Space`/`ShiftLeft`/`ShiftRight` ability.
split: p1 = WASD + `ShiftLeft` (also `Space`); p2 = arrows + `ShiftRight` (also `Enter`/`NumpadEnter`). `Escape` = quit prompt.
Split screen = two viewports via `renderer.setScissor`/`setViewport` (top = p1, bottom = p2), each with own chase camera and HUD.

### The Race and Car objects (shared with abilities.js / ghost.js)
```js
race = {
  THREE, scene, time /* seconds since GO, 0 during countdown */, state: 'countdown'|'running'|'finished',
  mode, cars: [Car], track, net /* session or null */, localPid,
  hazards: [],                  // owned by abilities.js (oil slicks etc.); abilities.js adds/removes meshes to scene itself
  hud: { flash(text, color) }   // game shows a big center message ~1s (for "ワープ!" etc.), on all viewports
       // + layer(car) -> that car's viewport element under its HUD (full-screen tints go there), or undefined
}
track = {
  curve /* THREE.CatmullRomCurve3, closed */, length /* m */, width,
  samples: [{ pos: Vector3, tan: Vector3 (unit), t }],   // N=1200 uniform by arc length
  nearest(pos, hintIndex?) -> { index, t, point, tangent, lateral /* signed m from center, + = right of travel */, dist },
  pointAt(t) -> Vector3, tangentAt(t) -> Vector3,   // t in [0,1), arc-length param, wraps
}
Car = {
  index, name, carId, def /* CARS entry */, stats, look,
  control: 'p1'|'p2'|'cpu'|'net',     // ghosts are NOT in race.cars
  mesh: THREE.Group,
  pos: Vector3, heading: number, speed: number /* signed forward m/s */, vel: Vector3 /* world, includes drift */,
  input: { throttle: 0..1, brake: 0..1, steer: -1..1 /* + = left */, ability: bool /* edge-triggered this frame */ },
  drifting: bool, offroad: bool,
  lap /* completed laps */, progress /* lap + t, monotonic-ish, used for ordering & ghost diff */, trackIndex,
  finished: bool, finishTime: number|null, bestLap: number|null,
  // per-frame modifiers: game resets to these defaults at the START of each frame, then calls updateAbilities(),
  // then runs physics honoring them:
  mods: { speedMul: 1, accelMul: 1, gripMul: 1, noCollide: false, noOffroadPenalty: false, invulnerable: false },
  spin: 0,          // seconds of spin-out remaining (set by abilities; game applies: steering randomized, grip≈0.2, speed decays)
  ability: {...}    // owned by abilities.js
}
```
Per frame order in game: input → reset mods → `updateAbilities(race, dt)` → if `car.input.ability` and car is local/cpu → `tryActivate(race, car)` → physics/collisions (skip car-car collisions if either `noCollide`; `invulnerable` car loses no speed on collision) → track progress/laps → ghost recorder sample → net send → render.
CPU cars: follow the spline with look-ahead; use ability when gauge full (after a random 0–4 s delay).
Remote ('net') cars: no local physics; shown where they are NOW: the last state is dead-reckoned (speed + yaw rate, arc) forward by its one-way latency `lat` + time since it arrived (capped at 1 s), and jumps between predictions are blended out by a critically damped offset (snap if > 15 m or > 90°). Math in `netpredict.js` (node test: `tools/check-netpredict.mjs`).
Physics feel: arcade. Offroad (|lateral| > width/2): speed cap ×0.55 (×0.775 with passive 'offroad'), unless `noOffroadPenalty`. Passive 'launch': accel +30% for 3 s after GO. Slipstream (stats.slipstream or passive 'draft'): within 25 m directly behind another car → +8% top (+16% with 'draft'). Drift: handbrake-free — sharp steer at speed with low grip breaks traction; `car.drifting` true while lateral slip is high.
Race length `TRACK.laps` (3). Countdown 3-2-1-GO. Lap counts only if car passed the half-way sample since last crossing. Results screen overlay is UI's job: game just calls onFinish once all local players finished (and for solo: others get estimated times from their current progress/pace; online: host decides placements, see net).

Effects (numbers from ABILITIES; duration×stats.abilityDuration, power×stats.abilityPower):
boost/nitro: speedMul & accelMul += power. oil: slick decal+mesh ~4 m behind the car, lives `duration` s; any other car touching it (radius 3 m) spins `power` s. shield: invulnerable (ignores collision slowdown, oil, timeslow). warp: move car forward `power` m along track center (keep lateral offset clamped inside road, set heading to tangent, keep speed), flash + particle burst. timeslow: all other cars get speedMul ×(1−power) for duration (shield ignores); only the activator is unaffected. phase: noCollide, noOffroadPenalty, speedMul += power, and make its mesh semi-transparent while active.
Show visual feedback for active effects (e.g. glow/flame for nitro, bubble for shield).
downforce: `mods.downforce = power` → game.js: grip 0.99 (course grip ignored), no drift (an ongoing one ends), no lateral slip or cornering scrub, steering at speed +25%×power, CPU lateral limit raised. robotdash: robot form for `duration` (carmodel.js `buildRobotMesh(look)`, parented hidden under car.mesh; the car's parts move into `ability.body`), 0.35 s transforms each way, invulnerable meanwhile; game.js `collide()` calls `robotKnock(race, a, b)` (abilities.js export): the other car (not shielded, local only — each client knocks its own cars) gets 12 m/s sideways, 0.4 s spin, speed ×0.7; after changing back speedMul/accelMul += power for 1.5 s.
hellchain (tp too): target = nearest car ahead by drawn progress, >6 m and ≤80 m (none → +0.15 for 1 s, '届かない!'). For `duration` s the target's own client gives it speedMul ×(1−min(power,0.6)) (several chains on one car: only the strongest) (+ '鎖につながれた!', `race.hud.shake(car, s)`); the owner's client tows it with `mods.tow` / `mods.towV` (game.js: +tow m/s² forward, throttle or not, up to towV = target speed ×(1+0.25 power); none while braking, spinning or off the road; a CPU only at full throttle, i.e. below its corner speed) toward 7 m behind the target and, for a player, assists the steering one lane beside the target's line (`mods.assist`, blended into the player's steer by game.js; only the player's own hard steer starts a drift; a CPU keeps its own line). Snaps on time out / ≤6 m / passed / either car finished or left → slingshot +0.45 for 1.5 s; a shield / phase / robot target snaps it at once (+0.15 for 1 s, no slow). Online release: the owner sends `{t:'ability', id:'hellchain', rel:1}` and every client also runs the same checks itself (timer, distance between the displayed cars, finish, immunity), whichever comes first — a lost or late 'rel' can't leave a remote chain dragging.

facewall: for `duration`, clones of the owner's mesh appear beside it a pair every 0.35 s (4.5 m apart, the outer ones piled against the barriers), spinning, riding along at the owner's track position; game.js `collide()` calls `faceWall(race)` (abilities.js export): this client's own cars (not shielded / phased / robot) just behind the owner and inside the wall's span are held ≥4.4 m behind it, along-track speed ≤ owner − 2 m/s (bounce on contact; gap measured square to the row of faces, so it holds in corners too); a remote owner silent ≥1 s (NET_STALE) neither blocks nor shows faces. ## net.js
Transport = public MQTT broker (see net.js header; tested working on GitHub Pages). Room code first char selects the broker. Host is authoritative for roster/start/results; game traffic (state/ability/finish) goes to a shared topic.
```js
export async function hostRoom(name) -> NetSession
export async function joinRoom(code, name, me? /* { carId, look }, sent with hello */) -> NetSession   // rejects with Japanese message on failure/timeout (10 s)
NetSession = {
  isHost, code, pid /* own id */,
  roster: [{ pid, name, carId, look }],        // host first. Max 4 players; 5th gets {t:'full'} and is closed.
  setMe({ name, carId, look }),                 // update own roster entry (sent to host, host rebroadcasts roster)
  on(type, fn) -> off(),  send(msg),  close(),
}
```
Events (`type`): `'roster'` (roster array), `'start'` ({ t:'start', roster }), `'state'`, `'ability'`, `'finish'`, `'results'`, `'leave'` ({pid}), `'closed'` (host gone / connection lost).
Messages game sends: `{t:'state', pid, x,y,z,h, s /*speed*/, lap, p /*progress*/, rt /*sender race time*/, ft? /*finish time*/}` ~20 Hz; `{t:'ability', ...}`; `{t:'finish', pid, time}`.
Host-only: `session.startGame()` → broadcasts `{t:'start', roster}` (also delivered locally). Host collects `finish` messages; when all players finished or 30 s after the first finisher, broadcasts `{t:'results', placements:[{pid, time|null}]}` (sorted). Game (on every peer) builds result.placements from that. If a pid leaves mid-race, treat as DNF.
Messages include `pid` of the original sender; session never delivers a peer's own message back to it.

## world.js
`export function buildWorld(ctx, def) -> { update(dt, time) }`. Builds, parameterised by the theme's `env`: sky dome, fog, hemi + sun (shadow camera follows the player as now), terrain (height fn + ground texture + vertex tint), road ribbon, shoulders, curbs, barrier walls (style per env), start/finish line + gantry + grid marks, and the minimap-independent `ctx.groundAt`. Then calls `theme.build(api)`.
Theme lookup: `{ forest: <inline in world.js>, city, desert, snow, beach }` via static imports of the theme files.
```js
api = {
  THREE, world /* Group to add to */, track, def, env, rnd /* seeded 0..1 */, night,
  near(x, z) -> [distToCenterline, centerlineY], groundAt(x, z) -> y,
  canvasTex(w, h, draw(g, w, h), repeat = true) -> CanvasTexture,
  isFree(x, z, r) -> bool   // true if a circle of radius r at (x,z) is outside barriers (dist >= width/2 + 12 + r) and not overlapping blockers
  block(x, z, r)            // reserve space (call for every big object you place)
  placeFacing(obj, sampleIndex, lateral) -> {x, z}   // put obj beside the track, local -Z facing the road
  onUpdate(fn(dt, time))    // per-frame animation hook
}
```
Theme module shape:
```js
export default {
  env: {
    sky: { top, horizon, bottom },                 // '#hex'
    fog: { color, near, far },
    sun: { dir: [x, y, z], color, intensity }, hemi: { sky, ground, intensity },
    exposure,                                      // renderer.toneMappingExposure
    night: bool,
    terrain: { base: '#hex', paint(g, w, h) /* 256² ground texture painter */, hills /* m */, rim /* m, mountains/dunes at the edge */, rimColor: '#hex' },
    road: { base: '#hex', line: '#hex', edge: '#hex' }, shoulder: '#hex',
    barrier: 'ads' | 'guardrail' | 'neon' | 'rock' | 'snowbank' | 'fence',
    curb: ['#hex', '#hex'],
  },
  build(api) {}   // scenery; may call api.onUpdate
}
```
Rules for themes: scenery never on or over the road (use isFree/block); budget ≤ ~150 draw calls and ≤ ~250k triangles for the whole theme (InstancedMesh / mergeGeometries); no external assets (procedural geometry + canvas textures only); nothing may block the chase camera's view along the road (keep tall things ≥ 20 m from the barrier on the inside of corners).
Themes: **city** night — skyline of lit-window towers (canvas window textures, emissive), neon signs in Japanese/English, streetlights (emissive heads; at most 4 PointLights total), elevated-road pillars where the road is raised, wet-look dark asphalt. **desert** sunset — sand dunes, red mesas/buttes, cacti, rock arches, tumbleweeds rolling (onUpdate), heat-haze-ish warm fog. **snow** day — snowy terrain, snow-covered pines, frozen lake, rocky cliffs, falling snow particles around the camera area (onUpdate, Points), snowbank barriers. **beach** day — animated ocean plane (shader waves, foam line) on the outside of the east side, sand, palm trees, beach huts/umbrellas, lighthouse, sailboats bobbing.

Roster message becomes `{ t:'roster', roster, trackId }`; `start` becomes `{ t:'start', roster, trackId }`. Guests keep `session.trackId` updated before emitting. The emitted 'roster' payload stays the roster array.

## net.js (v3) — low-latency state
- `p2p.js`: `createP2P({ selfPid, sendSignal(toPid, data), iceServers? })` → `{ connect(pid), handleSignal(fromPid, data), send(pid, obj) -> bool, isOpen(pid), rtt(pid) -> ms|null, onMessage(fn(fromPid, obj)), onOpen(fn), onClose(fn), close(pid?) }`. Native RTCPeerConnection, one negotiated unordered DataChannel (`maxRetransmits: 0`), JSON. STUN only. The smaller pid offers. Gives up quietly after 8 s, retries once 20 s later. Ping/pong every 1 s; `isOpen`/`send` report false 2.5 s after the last pong (one lost ping/pong is tolerated) (send still uses the channel). Never throws.
- Signalling over MQTT `${base}/s/<pid>` ({from, data}, QoS 1, not roster-filtered); broker RTT echo on `${base}/e/<pid>` every 2 s (QoS 0).
- `state` gets `q` (per-sender sequence) and `br` (sender's smoothed broker RTT). Sent on every open data channel; also published on MQTT (emqx thinning unchanged) while any roster peer has no live channel. Receivers drop `q <= last q` from that sender and set `lat` (ms, one way): P2P → rtt/2; MQTT → (sender br + own br) / 2, fallback 150. Only `state` travels over P2P (sender = the channel's pid); roster/start/ready/go/finish/results/ability stay on MQTT.
- Game traffic (`state`/`ability`/`finish`) carries the sender's current start `rid`; receivers drop it when both sides have a rid and they differ (a peer still on the last race's results screen keeps sending until its own 'start' arrives).
- `session.linkInfo()` → `{ [pid]: { p2p: bool, lat: ms|null, label } }` for the HUD (online, above the minimap; game.js shows `label`): '直結 45ms' / '中継 (旧版) 180ms' (peer's build predates P2P or is older than ours) / '中継 (直結不可) 180ms' (same build, no channel 10 s after linking) / '~' instead of ms while unmeasured (`lat` null; the 150 fallback is only for prediction, never shown).

## Build id / deploy (v4) — EVERY deploy runs `node tools/bump-build.mjs` first
- GitHub Pages lets browsers cache every file for 10 min and a normal reload keeps cached ES modules, so players ran old builds (no P2P → '中継 150ms' lag).

Don't hand-edit build.json / version.js / the `./` import map entries.

Every 5 min off-race and after each race: banner '新しいバージョンがあります [更新]'. Offline / no build.json: nothing happens; 更新 reloads only if the page re-fetch succeeded (else toast 'オフラインのため更新できません').
- Online: `hello` carries `v: BUILD`; roster entries (so `start.roster` too) carry `v` ('' = a build from before build ids). ## Graphics quality (v4)
- `save.quality`: `'auto'` (default) | `'high'` | `'medium'` | `'low'`; 設定 → 画質 (自動 / 高 / 中 / 低). ui.js passes it as `startRace({ quality })`.
- game.js `QUALITY` table, applied by `applyQuality(ctx)` at race start and live (never rebuilds the world):
  high = the original look (pixel ratio ≤ 2, PCFSoft 2048, all scenery). medium = pixel ratio ≤ 1.25, PCFSoft 1024 (one filter type on every level: lit shaders are compiled per shadow setup, so only shadows on/off needs other programs), instanced scenery ×0.6 and it stops casting shadows (cars / buildings / props still do), particles & skid marks ×0.6, fog ×0.8. low = pixel ratio 1 (0.8 on dpr ≥ 2 screens ≥ 1400 px wide), no shadows (a blob quad under each car instead), no MSAA (context attribute, so only when the race starts at 'low'), scenery ×0.35, effects ×0.3, fog ×0.6, world PointLights off, texture anisotropy 2. Split screen: pixel ratio ≤ 1 below 'high'. The ratio in use is `race.pixelRatio` (abilities.js sizes its point sprites with it: `race.pixelRatio ?? min(dpr, 2)`). MeshStandard + the room environment stay on every level (without them roads and car paint go near-black).
- auto: starts at 'high' with ≥ 8 cores and no coarse pointer, else 'medium' (or where the previous race of this page session ended). setup() also links the programs of the other shadow setup, so a step is a program-cache hit, never a mid-race recompile. Steps: 0 = 'low' at pixel ratio 0.7, 1 low, 2 medium, 3 high. Median rAF interval per window, 2 s during the countdown (first decision before GO) else 3 s, ignoring the first 1 s, 1 s after each change and gaps > 250 ms, and not measured behind the results overlay / quit prompt: > 20 ms → one step down; still > 20 ms at the lowest allowed step → back to the highest step whose median was within 12 % of the best (a 30 Hz rAF cap or a CPU-bound device gains nothing from lower settings) and never below it this page session; 5 windows in a row < 11 ms (only possible on > 60 Hz screens) → one step up, once per race, and if that step then measures > 20 ms it is the ceiling for the page session. Toast '画質を自動調整: 中' on level changes.
- world.js after any theme/scenery build (generic, nothing for themes to call): the ground sheet is split into 4×4 tiles sharing its buffers; every static InstancedMesh (≥ 16 instances, frustumCulled, not rewritten by an `onUpdate`) is split into 500 m cells (≥ 200 instances, or ≥ 15k triangles) and sorted by a position hash, so `count` thins it evenly and parts at the same position (trunk + crown) stay together. Set `mesh.userData.keepCount = true` on instanced parts that must never be thinned (rows of posts, streetlight pole/arm/head sets; kept sets of parts < 0.8 m cast shadows only at high), `'medium'` on ones thinned only at low (seated crowds); an instanced mesh whose matrices a theme rewrites only now and then (not every `onUpdate`) must set `frustumCulled = false`, or its matrices land in a mesh that was replaced by cells. Objects wholly deeper than the fog's end are hidden per view (`cull(camera)`), except ones whose materials all have `fog: false` (pre-hazed skylines, far clouds, an airliner: they stay visible beyond the fog); theme shaders with their own `fogNear`/`fogFar` uniforms (and `fog: false`) get them scaled with the level. camera.far stays 3000 (desert's sky dome and sun sit at 2000–2500 m). Below high: the fog (near + far) is also capped at 1500 m × the level factor (sceneries fog out at up to 3.2 km: ground tiles + cells); thinned sets of one geometry + material under `world` are drawn from a second set of 1000 m cells (kit cells and near/far sets merged: about half the draw calls; the fine cells stay for high's shadow pass); big merged statics (non-indexed, ≥ 6k triangles, radius > 500 m, at the origin straight under `world`) are split into 1000 m chunks at every level. `userData.minQuality = 'medium' | 'high'` on any object hides it below that level (heavy decoration).
- buildWorld returns `{ update, setQuality({ level, inst, far }), cull(camera) }`.
- Slow devices online: the frame dt cap is 0.1 s (was 0.05: under 20 fps the race ran in slow motion and that car fell behind in real time on everyone else's screen); `state` sends keep the timer remainder (a steady 20 Hz, was 12.5–20 Hz).

## Scenery modules (real circuits)
- A course def may set `scenery: '<id>'`; world.js imports `./scenery/<id>.js` (cached; missing/broken → plain base theme, warning only).
- `export default { base, env, baseBuild, build(api) }`: `base` = theme name (keep equal to the def's `theme`); `env` = partial env deep-merged over the base theme's env (plain objects merge, arrays/functions/values replace; `night` drives headlights); `baseBuild` (default true) also runs the base theme's `build(api)` first; then `build(api)` runs with the same api (+ `api.base` = base theme module; blockers shared). Must be synchronous.
- Quality thinning (v4) applies to scenery instancing too: `userData.keepCount = true` on sets whose gaps show or whose instances carry merged parts — buildings (roofs, crowns, warning lights, terraces sit on them), fences / posts / light towers (+ their glow sprites), lattices (dome, truss struts), lane buoys; seated crowds get `'medium'` (full at high / medium, thinned at low). A separate instanced part of a thinned object (roof, water tank) uses the same x, z as its body so both thin together. A set moving beyond its first-frame positions gets `frustumCulled = false` (its bounding sphere is cached).
- `def.time` is only the UI label: set sky/fog/sun/`night` in `env` to match it. Everything added to `api.world` is disposed on stopRace.
- Optional `def.label` replaces the base theme's name on the course chip (e.g. Sepang borrows 'beach' but shows 熱帯).
- A module that reuses another module's kit loads it with its own query (``await import(`./nring.js${new URL(import.meta.url).search}`)``), not a static import: world.js retries a failed module as `?retry=N`, and a failed static dependency stays failed under its plain URL.

## CPU difficulty (v5) — solo only
- data.js `DIFFICULTY` / `DIFFICULTY_BY_ID`: `easy やさしい ×0.8`, `normal ふつう ×1`, `hard つよい ×1.3`, `oni 鬼 ×1.7`, `legend 伝説 ×2.5` (`coinMul`), plus every CPU tuning number (car rarity weights, skill nodes, legend +8% top/accel, pace, corner factor, braking, line, drift, slipstream, mistakes, recovery, rubber band, ability tactics). Comments there say what each does.
- `startRace({ cpuLevel })` (default `'normal'` = the original CPUs, unchanged). Ignored outside solo (split / ghost / online have no CPUs).
- game.js: `normal` keeps the old driver. The other levels drive a per-track racing line (`racingLine`, built during loading) with a yaw-rate controller, take corners at `corner` x the car's real steering / grip limit, brake at `brake`, queue behind cars in corners and pass on straights (`PASS`: a car within `cone` m sideways caps their speed, never below 0; the pass path runs `gap` m beside it on the side with room and is held until `clear` m past it; in corners only a car under `stopped` m/s is driven round; no reset-to-road while waiting behind a stopped car); oni / legend drift through hairpins (`PIN`; none on courses with under `PIN.room` = 3 m of run-off, i.e. Monaco, where the slide ran into the barrier) and draft. Rubber band per level (`ahead` / `behind`; legend counts the gap behind in seconds).
- abilities.js `cpuAbility(race, car, { straight, corner, room })` -> reason string | false: per-ability tactics for 'smart' levels (hard+; `room` = m it can still go at its speed before it must brake: a warp needs straight and room > the jump + 45 m); game.js fires on a reason (kept in `car._.abilWhy`) or on any straight after `hold` s full (not oil / warp). A new ability with no rule there is used on straights.
- Cars away in an ability's own space (tokyodive: `car._.away` / `ability.away`, a parked CPU or a hidden remote diver) are skipped by the AI's follow / pass / draft loop, by `cpuAbility` (its rivals) and by `faceWanted`. A difficulty CPU coming back from a dive lands on its racing line (`track.line`), heading along it; 'normal' CPUs (no line) land as before.
- save.js `save.lastCpuLevel` (validated, default 'normal'). ui.js: 5 chips under CPUの数 on the solo screen; results show `コース ・ CPU <name>`, a `CPU <name> [n/m台に勝利] 賞金×<x>` line (the place prize x x, on top of the course multiplier: x = coinMul below 1, else 1 + (coinMul − 1) · CPUs beaten / CPUs, so last place pays like ふつう; best-lap / ghost bonuses take the course multiplier only) and a `伝説 撃破` badge for a legend win.

CDN files are best effort. Then `skipWaiting`. Activate: deletes every other `ngp-<digits>` cache, drops `ngp-cdn` entries missing from `CDN`, then `clients.claim`.
  - Routing (GET only). Same origin: `?v=<this build>` → cache-first; `?v=<other build>` (an older tab) → not intercepted; `.glb/.png/.svg` → stale-while-revalidate; everything else (page, `build.json`, `version.js`, manifest, `?retry=` imports) → network-first, falling back to this build's copy offline (ignoreSearch). Cross origin: `cdn.jsdelivr.net/npm/<pkg>@<ver>/` and `www.gstatic.com/firebasejs/<ver>/` → cache-first `ngp-cdn`; `fonts.googleapis.com` → stale-while-revalidate. **Never intercepted:** other cross-origin traffic (Firebase Auth / RTDB, MQTT broker, font files on fonts.gstatic.com, STUN, emulators), non-GET requests, and other builds' `?v=` files. A new CDN library must use a version-pinned URL to be cached offline. A new asset type needs the stale-while-revalidate regex.
  - Update flow: deploy (bump) → ui.js's `build.json` check (v4) reloads the page onto `?v=<new>` modules (the old worker passes them to the network). Meanwhile the navigation installs the new sw.js, which precaches the new build, takes over and deletes `ngp-<old>`. End state: one active worker and one shell cache, and the tab runs only new modules. Offline, the installed build boots from its cache. Car models first loaded before the worker took control are cached on the next online visit (until then an offline race uses the procedural cars).

## Cloud save (v6) — `sync.js`, Firebase (same project / SDK / anonymous uid as lb.js)
- 設定 → データ連携（クラウドセーブ）: the player's own devices share one save, linked by a code, no login. [連携を始める] makes a sync group `g` (24 random chars) with this device as its first member and uploads the save; [コードを入力] joins one; linked: status line, device list (label from the UA like 'Windows PC・Chrome' / 'iPhone・Safari' / 'iPhone・アプリ', + last seen), [今すぐ同期] [端末を追加] (a new code) [連携を解除] (this device only, keeps its local data; the last device also deletes the cloud copy). A topbar cloud icon on home: ✓ synced / ↻ syncing or unsent / ⚠ conflict, error or link lost. Ghosts and the device settings `quality` / `sound` are never synced.
- Link code: 6 chars of `23456789ABCDEFGHJKLMNPQRSTUVWXYZ` (sync.js `CODE_ABC`, ~1e9), valid 10 min (countdown, copy), single use, shown in a monospace font.
- Firebase: `saves/<g> = { data /* pwa.js encodeSave(), decoded with decodeSave() */, rev, at, by }`, `members/<g>/<uid> = { label, seen, code? }`, `codes/<CODE> = { g, exp, by /* uid */ }`, `own/<uid> = g` (the group this uid started last). Rules (tools/gen-rules.mjs → database.rules.json, test: `node tools/check-sync-rules.mjs` on the emulators): a code is read by exact path only (no listing), created only by a member of its group (checked against the state after the update, so start = member + save + code in one update), never rewritten, deleted by its creator or a member; `exp` ≤ now + 10 min. A membership is written only by its own uid, and created only for a new group (no members, no save, named by `own/<uid>` in the same update) or for a group that has a save, with a live code of that group that the same update deletes. Members may remove themselves, the last one only together with the save; `own/<uid>` (read / written by that uid only, never deleted) is repointed only once the uid is out of the group it names or leaves it in the same update. So one sign-in holds at most one group it started and no save outlives its members: saves ≤ uids, like the per-uid bound on ghosts (codes, ~100 B, are not counted). sync.js [連携を始める] reads `own/<uid>` and, if this device is still in that group (its local link was dropped without leaving), leaves it in the same update; [連携を解除] re-reads the member list for the last-member check (and once more if the write is denied). the save is read / written by members only, `data` ≤ 200 000 chars, `rev` = old + 1 (1 when new) on every write, `at` = now, `by` ≤ 24 chars; only the last member may delete it. No group size cap: rules can't count children, and a device that lost its sign-in keeps its entry forever (only a member removes itself), so a cap would lock players out over time; outsiders can't grow a group (single-use codes made by members only).
- Local: localStorage `ngp.sync` = `{ g, uid, rev /* last synced */, h /* fingerprint of the save then */, dirty, at, synced, sent }` or `{ lost: true }`. Linking needs working localStorage ([連携を始める] / [コードを入力] refuse when it is blocked: a download could not be kept). save.js `setPersistHook` fires on every `persist()`; sync.js marks dirty when the fingerprint (FNV of the save JSON without quality / sound) differs; each sync step also counts a fingerprint that differs from `h` as dirty (a change another tab, e.g. an old build's, wrote without the hook). `at` = the server's clock (`Date.now()` + `.info/serverTimeOffset`), as the chooser shows it next to the cloud's `at`.
- Upload ~3 s after a change, when the page is hidden, on 'online' / reconnect, after a race (ui.js `syncKick()` in endRace): `set(saves/<g>, rev + 1)`, which the rules turn into a compare-and-set. Download at start, when shown again, and on a listener on `saves/<g>/rev`: cloud rev ≠ ours and not dirty → apply (backup first, `replaceSave` in place, ui.js redraws); if the backup or the save can't be stored (storage full) nothing changes and it is not recorded as synced ('⚠ この端末に保存できませんでした…', retried every minute). Both changed → an in-page chooser (この端末のデータ / クラウドのデータ with coins / tickets / cars / races / last update / device; the unchosen side is kept as a backup; あとで選ぶ = Esc / back; it opens on its own, so focus starts on あとで選ぶ). Joining with progress on this device shows the same chooser (+ 連携をやめる). Nothing is applied and the chooser doesn't open during a race, a dialog, the gacha reveal or in an online room (ui.js `idle()`: the host may start any moment); it waits. `launch()` closes an open chooser (= あとで選ぶ). Offline: stays dirty, sent when back.
- Every overwrite of local data (download, transfer code import, すべてリセット, 元に戻す) first stores the old save in `ngp.save.bak` (save.js `backupSave` / `backups`): the last 3 (a conflict's unchosen side, transfer code, reset, 元に戻す), plus the latest routine download (`auto`) in a slot of its own, so downloads never push those out; a routine download whose backup doesn't fit waits instead of dropping others. 設定 → データ連携 → 元に戻す restores one, picked by its time, not its place in the list (and syncs it); a restore that can't be stored changes nothing. Resetting while linked resets the linked devices too (the dialog says so).
- Link lost: the stored uid is not the signed-in one (storage / IndexedDB cleared, e.g. Safari's 7-day eviction) or the save read is denied → '連携が切れました。もう一度コードで連携してください', local data kept.
